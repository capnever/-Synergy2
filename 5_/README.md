# Кейс задача 5

<p>В рамках кейс-задачи №5 разработаны предложения по устранению и снижению влияния проблем, выявленных в ходе аналитического обзора чат-бота CarZona72.</p>
<p>Предложения сформированы на основании результатов тестирования и анализа, проведённого в кейс-задаче №4.</p>

<hr>
<h2>Задача</h2>
<p>Необходимо на основании проведённого анализа определить выявленные проблемы и предложить способы их устранения или дальнейшего совершенствования разработанного чат-бота.</p>

<hr>
<h2>Решение</h2>
<h3>Повышение точности распознавания</h3>
<p>Основной проблемой текущего прототипа является ограниченность правилового распознавания.</p>
<ul>
<li>расширить словарь синонимов и разговорных формулировок;</li><li>добавить обработку распространённых опечаток;</li><li>учесть дополнительные словоформы;</li><li>собирать неизвестные запросы для дальнейшего расширения правил.</li>
</ul>

<h3>Использование NLP</h3>
<p>На следующем этапе можно перейти от простого поиска ключевых слов к классификации пользовательских намерений: узнать услугу, узнать адрес, узнать график, записаться, подобрать запчасть, связаться с оператором.</p>

<h3>Хранение заявок</h3>
<p>В текущем прототипе состояние пользователей хранится в памяти приложения. Для постоянного хранения рекомендуется подключить SQLite или PostgreSQL.</p>
<p>В базе можно хранить:</p>
<ul>
<li>идентификатор клиента;</li><li>Telegram ID;</li><li>услугу;</li><li>дату и время записи;</li><li>VIN или номер кузова;</li><li>описание запчасти;</li><li>статус заявки;</li><li>дату создания заявки.</li>
</ul>

<h3>Развитие операторского режима</h3>
<p>Для полноценной работы оператора рекомендуется реализовать:</p>
<ul>
<li>список новых заявок;</li><li>уникальный номер заявки;</li><li>статусы заявки;</li><li>кнопку «Взять в работу»;</li><li>отправку ответа конкретному клиенту;</li><li>закрытие заявки.</li>
</ul>

<h3>Безопасность</h3>
<ul>
<li>не хранить Telegram-токен в исходном коде;</li><li>использовать переменные окружения;</li><li>не публиковать конфиденциальные данные клиентов;</li><li>ограничить доступ операторов к заявкам.</li>
</ul>

<h3>Постоянное развёртывание</h3>
<p>Текущий бот работает только при запущенном экземпляре программы. Для постоянной работы рекомендуется разместить приложение на сервере или VPS и запускать его как фоновый сервис.</p>

<h3>Расширение Telegram-интерфейса</h3>
<ul>
<li>добавить кнопки подтверждения даты и времени;</li><li>кнопку связи с оператором на основных этапах;</li><li>карточку заявки перед подтверждением;</li><li>понятные статусы заявки;</li><li>единый стиль сообщений и кнопок.</li>
</ul>

<h3>Мониторинг и статистика</h3>
<p>Для дальнейшего анализа эффективности можно сохранять обезличенную статистику: количество обращений, популярные услуги, успешные записи, неизвестные запросы и обращения к оператору.</p>

<h2>Заключение</h2>
<p>В ходе выполнения кейс-задачи №5 определены основные направления дальнейшего совершенствования чат-бота CarZona72.</p>
<p>Наиболее важными улучшениями являются постоянное хранение заявок, полноценный операторский контур, безопасное хранение токена, серверное развёртывание и повышение точности распознавания пользовательских запросов.</p>
<p>Реализация предложенных решений позволит перейти от учебного прототипа к более устойчивой информационной системе, которую можно использовать в реальной работе автосервиса.</p>
